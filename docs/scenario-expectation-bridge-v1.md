# 상황형 퀴즈와 최신 장소 분석 연결

사용자 결정(2026-09-14)에 따라 기존 상황형 12문항·선택지·프로필 디자인을 유지한다. 기본 흐름은 `/start` → `/quiz` → `/profile` → `/recommendations/a-{run_sha256}`이며, 프로필에서 사용자가 추천 버튼을 눌러야 추천을 생성한다. 선택적 사진은 `/photo`에서 추가한다. 독립 경험 문항을 사용하는 `/trip`은 계속 제공한다.

## 변환 규칙

- 입력: 기존 `questionnaire-v2`의 원래 선택 답변과 정확한 `config_hash`. 서버가 고정 채점표로 다시 계산하며 클라이언트 점수는 받지 않는다.
- 기존 축별 원점수 비율을 합계 10,000의 정수 가중치로 정규화한다. 나머지는 소수부가 큰 순서, 동률은 H/E/R 순으로 배분한다.
- 장소 H/E/R은 최신 분석의 독립적인 0–100점이다. 확인된 장소 축 값의 가중 평균으로 추천한다. 사용자가 세부 항목의 강도·회피를 직접 답한 것으로 변환하지 않는다.
- 가장 높은 선호 비중의 축(동률 포함)이 미확인이거나 전체 가중치의 절반 미만만 확인되는 장소는 제외한다. 미확인을 0점으로 대체하지 않는다. 남은 가중치는 확인된 근거에 재배분한다.
- 직접 확정한 사진 분위기가 있을 때 경험 비중은 8,000, 사진 분위기 비교는 2,000으로 배분한다. 기존 장소 사진 분위기 근거와 비교하며, 사진만으로 역사적 사실을 확정하지 않는다.
- 지역과 근거가 확인된 필수 시설을 필터로 적용한다. 날짜·시간·동행·이동수단·도보·실내외·혼잡 선호는 방문 계획으로 보존하되 현재 점수에 반영하거나 당일 상태를 보장하지 않는다. 화면에서 적용 범위를 설명한다.
- 신뢰도·사진 수·SNS 게시물 수를 별도 인기 가산점으로 사용하지 않는다. 최신 장소 분석에 이미 반영된 자료와 결측 상태는 그대로 따른다.

이 연결은 상황형 선택의 상대 선호를 활용하는 명시적 구현 규칙이다. 독립 척도 설문과 동등하거나 사람 만족도로 검증되었다고 주장하지 않는다.

## API와 재현성

`POST /v1/authenticity/scenario-profiles`는 `scenario-expectation-bridge.v1`을 받는다. 기존 `/profiles`와 공통 세션·사진 소유권 검사를 사용한다. 이후 공통 `/runs`, 상세·비교·저장·피드백 API를 사용한다. 추천 버전은 `scenario-axis-bridge-ranking.v1`이다. 원래 답변·여행 조건·사진 영수증·장소 분석 버전·기여 근거를 불변 JSON 스냅샷으로 보존한다.

같은 입력의 실패 후 재시도는 같은 요청 ID를 사용한다. 변경된 입력은 새 요청 ID를 사용한다. 사진 원본은 저장하지 않으며 다른 세션의 사진 영수증이나 추천을 사용할 수 없다. 기존 `/trip` 요청·추천 버전과 과거 추천 주소는 유지한다.

새 테이블이나 환경변수는 필요하지 않다. 웹과 백엔드 이미지를 함께 갱신해야 새 엔드포인트를 사용할 수 있다. PUBLIC 데이터 설치와 기존 세션 설정은 유지해야 한다.

## 검증 구분

현재 PUBLIC 1,984곳을 사용하는 로컬 PostgreSQL/API에서 H/E/R 중심 입력, 지역 필터, 결과 재조회, 사진·주소·근거, 비교·저장을 확인한다. PC·모바일 브라우저에서 기존 흐름과 `/trip`을 각각 검사한다. 공식 사진이 없는 장소는 미확인으로 표시한다. 사진 업로드·확정·삭제의 기술 검증에는 명시적으로 표시한 합성 제공자 fixture를 사용하며 유료 모델 호출이나 사람 평가는 수행하지 않는다.
