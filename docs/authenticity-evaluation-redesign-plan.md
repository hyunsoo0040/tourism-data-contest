## 1. 확정된 방향과 결정이 남은 항목

### 이미 정해진 원칙

- H는 객관적 진정성, E는 구성적 진정성, R은 실존적 진정성을 기반으로 설계한다.
- 세 축은 동시에 높거나 낮을 수 있다. 합계를 100으로 맞추거나 하나의 성격 유형으로 강제하지 않는다. 여기서 독립 축은 설계상의 구분이며, 통계적 무상관이 입증됐다는 뜻은 아니다.
- 장소 점수는 진정성 자체의 객관적 측정값이 아니라 **해당 경험을 지원하는 장소 특성의 근거 기반 평가**다. 실제로 느낀 진정성은 방문자 응답으로 확인한다.
- 사진은 보이는 분위기·외관·환경만 분석한다. 이 관찰을 허용된 하위 항목에 연결할 수 있지만, 사진에 역사 사실·운영·접근성·혼잡·내면 경험을 판단하는 권한을 부여하지 않는다.
- Instagram은 사회적으로 유통되는 이미지와 기대를 분석하는 자료다. 게시물 수를 진정성·방문 만족도·방문객 수로 치환하지 않는다.
- 전국 볼거리·체험만 다룬다. TourAPI 유형 12·14·28을 유지하고 음식점·숙소는 제외한다.
- 기존 2,000곳의 원본, 분석, 실패·복구 이력, 평가 보고서를 보존한다. 기존 개발 자료를 블라인드 표본으로 재명명하지 않는다.
- GLM은 현재 **동시 5세션**을 공유하며 전체 40세션 상한도 지킨다. 공식 자료 API 한도는 중단, GLM 429는 공통 대기 후 재시도 정책을 유지한다.

## 4. 이론에서 측정 항목까지 연결

Wang은 객관적·구성적 진정성과 활동을 통해 경험하는 실존적 진정성을 구분한다. 실존적 진정성은 개인 내적 경험과 사람 간 경험을 포함한다. 따라서 아래 H/E/R은 이론을 서비스에 맞게 측정 항목으로 옮기는 설계이며, 원논문이 검증한 3축 점수 척도라고 설명하지 않는다. [Wang, 1999](https://s3.amazonaws.com/arena-attachments/1198636/01d3e4790be40893bb3ef63b88afdc29.pdf?1502885485=)

관광자의 시선은 E만의 전용 원리가 아니다. 역사 유산에 대한 기대나 “자연 속에서 자신을 찾는다”는 기대도 사회적으로 형성될 수 있다. E에서는 특히 **대상에 부여된 이미지와 상징을 경험하려는 측면**을 구분해 측정한다. 사진을 보는 것 외의 감각·활동도 함께 다룬다. [Larsen & Urry, 2011](https://journals.sagepub.com/doi/10.1068/d21410)

### 장소 하위 항목 초안

| H | H.b 역사·출처의 구체성 | 해당 대상의 연혁·인물·사건·출처를 이해하는 경험 | 텍스트 길이·연도 수를 가치로 환산 |
| H | H.c 전통의 실제 지속 | 지역 주체의 전승·의례·공예·생활문화와의 연결 | 전통풍 장식·상업 공연만으로 전승을 단정 |
| H | H.d 원형 맥락의 탐구 | 원형·유산·전통과 연결된 해설·학습·탐방 | 일반 강연·독서 활동을 역사 학습으로 환산 |
| E | E.a 공유되는 상징·의미 | 낭만·레트로·청춘 등 해당 장소에 부여된 의미 | 예쁘다는 문장만으로 사회적 의미를 확정 |
| E | E.b 매체를 통한 이미지 유통 | 작품·광고·관광 홍보·SNS를 통한 이미지의 재현·확산 | 게시물 수만으로 구성적 진정성 전체를 산출 |
| E | E.c 이미지의 시각적 표현 | 외관·경관·연출이 장소 이미지와 연결되는 방식 | 미적 우열을 보편적인 단일 점수로 단정 |
| E | E.d 이미지의 체험·재현 | 대표 장면·구도·이야기를 방문자가 경험하고 재현할 기회 | 포토존이 있다는 이유로 모든 방문자가 같은 의미를 느낀다고 판단 |
| R | R.a 일상에서 벗어날 여지 | 자율적 탐색·여유·자기 선택을 지원하는 경험 | 외진 곳이면 자유롭다고 추정 |
| R | R.b 회복을 지원하는 환경 | 자연·시각적 저자극·머무를 환경의 근거 | 녹지 사진으로 실제 소음·혼잡·심리적 회복 확정 |
| R | R.c 참여·도전·몰입 | 만들기·신체 활동·탐방·집중할 활동의 기회 | 체험시설의 존재를 실제 몰입 경험으로 단정 |
| R | R.d 관계·자기표현 | 함께 만들고 교류하거나 자신을 표현할 활동의 근거 | 단체 관광객이 보인다는 이유로 유대감 추정 |

각 항목은 0–4의 행동·경험 앵커와 별도 UNKNOWN을 갖는다. 0은 낮음을 지지하는 근거가 있을 때만 사용한다. 자료에 해당 내용이 없으면 UNKNOWN이다. 0–100 축 변환은 표시 방식이며 정밀한 심리 측정값처럼 제시하지 않는다.

기존 M1–M6는 별도로 정합성을 검토한다. 예를 들어 현대적 재해석이 높다고 H가 자동으로 낮아지지 않으며, M3 현장 밀도는 사진·SNS 건수로 채우지 않는다. M 특성과 경험 축 사이의 중복 기여도 점검한다.

## 5. 사진의 축 기여와 시각적 검증

### 출처별 권한

| 사진으로 얻은 관찰 | 가능한 기여 | 추가 조건 / 금지 |
|---|---|---|
| 전통적 외관·공간 구성 | E.c의 이미지 표현, 조건부 H의 공간 경험 보완 | 공식 자료로 해당 대상의 역사·유산 성격이 확인돼야 H 보완 가능. 원형·연대·진위는 사진으로 확인하지 않음 |
| 색·조명·대표 경관·연출 | E.c, E.d의 일부 시각적 단서 | “반복되는 관광 촬영 구도”는 복수 자료로 확인. 한 사진만으로 유행·상징의 공유를 확정하지 않음 |
| 녹지·물·개방감·시각적 자극 | R.b의 환경 단서 | 실제 고요함·보행 안전·접근성·체류 허용 여부는 별도 자료 |
| 감각적 체험 공간의 외관 | E.c의 연출, R.c 판단의 보조 설명 | 활동의 존재·운영은 텍스트 확인. 참여자의 실제 몰입·감정은 사진에서 추정하지 않음 |
| 사진에 사람이 없거나 많음 | 촬영 순간의 장면 기록 | M3 현장 혼잡, 상시 고요함, 향후 방문 조건으로 사용하지 않음 |

H는 사진만으로 점수가 생기는 경로를 두지 않는다. 공식 역사 사실과 연결된 시각 관찰이 H의 경험 평가를 실제로 개선하는지는 별도 실험으로 결정한다. 효과가 없으면 H 기여는 끄고 E/R 기여만 유지할 수 있다.

### 구현 작업

1. 기존 2,507장의 원본 연결·권한·중복·해상도·장소 대응·대표성 이력을 다시 감사한다. 파일이 있다고 성공으로 표시하지 않는다.
2. 같은 장소의 사진을 중복 구도·주야간·계절·실내외로 묶고 대표 사진을 선정한다. 사진이 많은 장소에 점수가 누적되지 않도록 장소별 기여 단위를 고정한다.
3. GLM의 현재 분위기 결과는 정의가 같은 관찰에만 재사용한다. 새 관찰 항목은 새 프롬프트·스키마로 분석하고 구버전 캐시와 구분한다.
4. `시각 관찰 → 허용된 하위 항목 → 축 기여`의 매핑을 모델 바깥의 버전 정책으로 구현한다. 사진이 텍스트의 사실 권한을 상속하지 않게 한다.
5. 같은 특징이 텍스트·사진에 함께 등장하면 같은 하위 항목의 근거로 합친다. 두 출처가 있다는 이유로 두 번 가산하지 않는다.
6. 사진끼리 또는 텍스트와 사진이 충돌하면 서로 다른 촬영 시점·구역·관찰 범위를 먼저 확인한다. 해결되지 않으면 단일 확정값으로 평균해 숨기지 않고 충돌 상태를 보존한다.
7. 사용자 업로드 사진은 원하는 분위기의 입력으로 사용하고 사용자가 수정·확정할 수 있게 한다. 사진으로 사용자의 역사 취향·내면 상태를 추정하지 않는다. EXIF 제거·원본 기본 미보관·삭제 확인을 유지한다.

### 실제 사진 검수

전체 자동 감사와 사람의 시각적 검수를 분리한다. 기본 작업량은 **개발 사진 180장 + 새 평가 사진 60장, 합계 240장**이다. 장소별 최대 3장을 원칙으로 하며, 확보 여부에 따라 실행 전에 최종 목록을 동결한다. 부족한 사진을 중복으로 채우지 않는다.

검수자 두 명이 모델 태그·점수를 보지 않고 사진을 직접 보고 관찰 유무·강도·미확인·장소 연결·대표성 한계를 기록한다. 이후 모델 관찰과 비교하고, 마지막으로 축에 연결한 판단의 적합성을 별도로 검토한다. 사진 인식이 맞아도 축 연결이 틀릴 수 있기 때문이다.

검수 결과에는 사진 수, 고유 장소 수, 출처·계절·주야간 구성, 검수자 수와 불일치를 기록한다. **240장 표본 검수를 2,507장 전수 의미 검증으로 표시하지 않는다.** 사람 검수 전의 자동 모델 재평가는 진단으로만 사용한다.

## 6. Instagram 수집과 E축 적용

### 수집 범위와 데이터의 뜻

Apify의 `apify/instagram-hashtag-analytics-scraper`를 첫 후보로 사용한다. 문서상 `postsCount`와 인기·최근 게시물 표본을 제공한다. 이는 아직 IT-DA의 한국어 장소에서 정확성·누락률·신선도를 실측한 결과가 아니다. [Actor 문서](https://apify.com/apify/instagram-hashtag-analytics-scraper)

첫 단계는 40곳, 장소당 최대 3개 태그의 소규모 탐색이다. 유명/덜 알려진 장소, 동명 장소, 별칭, 긴 한국어 명칭, 태그가 없을 가능성이 있는 장소, 세 유형과 두 기존 묶음을 포함한다. 성공 태그만 선별한 뒤 전체 성공률이라고 보고하지 않는다.

| 저장 항목 | 의미 |
|---|---|
| `reported_tag_posts_count` | 공급자가 해당 태그에 대해 보고한 관측 시점의 수치. 실제 방문객·고유 방문·기간 내 신규 게시물 수가 아님 |
| `reported_count_raw` | 원래 표기와 정수 변환 여부. 반올림·단위 표기·정밀도 보존 |
| `sample_posts` | 실제 반환받은 인기/최근 게시물 표본. 모집단 전체 또는 무작위 표본으로 취급하지 않음 |
| `observed_relevant_posts_count` | 받은 표본 안에서 해당 장소와 관련된 것으로 확인한 고유 게시물 수 |
| `represented_meanings` | 표본·공식 홍보·작품 자료에서 확인된 장소 이미지와 상징. 각 근거를 연결 |
| `source_role` | 공식 홍보 / 명시적 광고 / 일반 게시 / 미확인. 불분명하면 미확인 유지 |
| `collection_state` | AVAILABLE / EMPTY_CONFIRMED / UNAVAILABLE / AMBIGUOUS / STALE 등 원인별 상태 |

조회 실패·태그 미지원·장소 대응 불명확은 0개가 아니다. `postsPerDay`는 정의·관측 기간·정확성이 검증되기 전 핵심 점수에 사용하지 않는다. 2회 스냅샷의 차이도 삭제·집계 방식 변화가 섞일 수 있으므로 바로 “신규 게시물 수”로 부르지 않는다.

### 장소와 태그의 대응

- 공식 명칭·지역·검토된 별칭으로 후보를 만들고 `장소↔태그` 연결표를 버전 관리한다.
- 지역 전체 태그, 동명 상점·인물·작품 태그를 특정 관광지에 자동 귀속하지 않는다.
- 게시물 표본의 캡션·명시된 장소 정보로 대응을 검토한다. 인기 표본에서 관측한 관련 비율을 태그 전체의 정확한 관련 비율로 확대하지 않는다.
- 같은 게시물이 여러 태그에 중복되므로 총수를 단순 합산하지 않는다. 초기 점수 실험은 **건수를 보기 전에 정한 대표 태그 하나**를 사용하고, 별칭 태그는 별도 수치로 표시한다. 고유 게시물 합집합은 실제 수집 표본에 대해서만 계산한다.
- 명칭 대응이 불확실한 태그는 자동 점수에서 제외하고 검수 대상으로 남긴다.

### E축으로 연결하는 방식

E.b에서 `유통 규모`와 `유통되는 의미`를 분리한다. 게시물 수는 전자에만 근거가 된다. 후자는 캡션·해시태그의 반복 표현, 공식 관광 서사, 확인된 작품·매체 연관성으로 판단한다. 광고도 구성적 이미지의 자료지만, 방문자가 실제로 그렇게 느꼈다는 증거로 바꾸지 않는다.

원시 건수는 그대로 선형 가산하지 않는다. `log1p` 변환, 이상치 영향 상한, 관측 시점 통일을 후보로 비교하고 변환 기준은 개발 자료에서만 정한다. 지역·유형별 상대 순위는 편중 진단용으로 보고하며, 지역마다 같은 유명세를 강제하는 식을 기본값으로 두지 않는다.

E.b의 SNS 기여에는 상한을 둔다. 상한과 가중치는 결과를 보고 임의로 키우지 않고 개발 평가 후 동결한다. SNS가 없으면 E 전체를 낮추지 않으며, 다른 매체의 이미지 근거가 있는 장소도 평가할 수 있어야 한다. SNS 이용 여부에 따른 E 비교 가능성과 추천 노출 차이를 별도로 검사한다.

SNS를 E에 반영한 뒤 최종 추천에서 인기 보너스를 다시 더하지 않는다. E를 중요하게 여기지 않는 사용자에게 게시물 수가 직접적인 가산점으로 작동하지 않게 한다. SNS가 많은 장소를 더 높은 신뢰도라는 이유로 우대하지 않는다.

### 저장·비용·운영

Apify는 현재 공공데이터 전용 `SourceReceipt`에 가짜 공공데이터 ID를 넣어 연결하지 않는다. provider 유형이 구분되는 새 수신 기록을 만들고 Actor ID·build ID·실행 ID·입력 해시·관측 시각·결과 해시·가격표 기준일·실제 비용을 보존한다. 계정 토큰을 URL·로그·보고서에 포함하지 않는다.

첫 수집은 집계와 필요한 텍스트 표본을 중심으로 한다. 게시물 이미지의 공개 접근성과 재이용 권한을 동일시하지 않고, 이미지 다운로드·공유 범위는 따로 결정한다. 공개 평가 보고서는 집계·비식별 검토 결과 중심으로 구성하고, 불필요한 계정 프로필·댓글·사용자 정보는 수집하지 않는다.

예산·권한·자료 한도에 도달하면 해당 수집을 PAUSED로 두고 유효한 이전 스냅샷을 보존한다. Apify의 제한 처리는 GLM 429 무기한 대기 정책과 분리한다. 비용 상한 미정 상태에서는 유료 확대를 시작하지 않는다.

## 7. 분석 파이프라인과 점수 계산

전체 흐름은 `원본·수신 기록 → 장소 대응 → 사실/서사/시각/SNS 관찰 → 하위 항목 판단 → 축 집계 → 사용자 기대와 비교 → 추천·설명 → 실제 평가`다. 자료 수집과 모델 판단, 결정적 집계를 분리한다.

### 구조적 변경

- 원본 사실, 매체가 표현한 의미, 시각 관찰, 사회적 확산 지표, 모델 추론을 서로 다른 유형으로 저장한다.
- 모든 항목에 출처 ID·해시·주장 대상·관측 범위·시점·직접 관찰/추론/미확인·판단 이유·정책 버전을 남긴다.
- 새 출처 권한은 provider 이름만으로 결정하지 않고 **주장 유형과 하위 항목의 조합**으로 결정한다. SNS 수치는 SOCIAL_CIRCULATION만, 사진은 VISUAL_MOOD/외관 관찰만 직접 뒷받침한다.
- 텍스트의 근거 문장과 수신 원문 사이의 위치를 보존한다. 문자 정규화로 복구한 인용은 원문 범위로 되돌려 저장하고 `EXACT`와 `NORMALIZED_AND_MAPPED`를 구별한다. 의미 유사도 검색은 후보 찾기에만 사용한다.
- 모델 응답의 항목 오류는 누락·중복·스키마·인용·권한·의미 의심으로 분류한다. 정상 항목과 실패 항목을 분리해 보존하고, 제한된 재생성에 동일한 규칙을 적용한다.
- 자동 의미 검토 모델은 의심 사례를 찾는 보조 수단이다. 동일 모델의 재동의를 사람 정답이나 검수 통과로 사용하지 않는다.

### 집계와 자격

1. 하위 항목의 값은 고정 앵커로 평가하고, 축은 명시된 식으로 계산한다. 온라인 LLM이 최종 점수를 결정하지 않는다.
2. 현재의 “4개 중 아무 2개” 규칙을 핵심 의미 조건으로 보완한다. H는 실제 역사·유산·전통의 접촉 근거, E는 장소에 부여된 의미의 근거, R은 경험을 지원하는 구체적 조건·활동의 근거가 필요하다.
3. 항목 개수·출처 개수·사진 장수·SNS 건수가 신뢰도 보너스로 점수에 들어가지 않는다. 신뢰도는 해당 판단을 사용할 수 있는지 판단하는 필터다.
4. 점수와 함께 확인된 항목, 미확인 항목, 출처 기여, 충돌을 제공한다. 적은 항목의 평균이 장소 전체를 대표하는 것처럼 보이지 않게 한다.
5. 사용자가 중요하다고 밝힌 축이 미확인인 후보는, 다른 축만으로 높은 적합도를 만들어 강한 추천으로 내보내지 않는다. 근거 충분 후보를 우선 구성하고 부족하면 부족한 이유와 실제 가능한 결과 수를 반환한다. 부족한 5개를 억지로 채우지 않는다.
6. 사진·SNS 부재는 0점으로 대체하지 않는다. 누락 시 가중치 재분배가 특정 후보에 유리해지는지 공통 관측 항목 비교와 누락 모의 실험으로 검사한다.
7. 이론이 바뀐 축은 이전 숫자와 의미가 다르다. 구·신 점수의 차이를 같은 척도의 개선량처럼 보고하지 않는다.

새 경험 축에 이미 반영한 사진 특징과 기존 분위기 유사도 15% 채널의 중복을 검사한다. 기본 실험은 중복 특징의 추가 가산을 끄며, 별도 분위기 채널을 유지하려면 축에서 사용하지 않은 세부 취향 비교 역할을 명시해야 한다. 기존 15%나 임의의 새 비율을 검증 없이 그대로 승계하지 않는다.

## 8. 사용자 설문·추천·피드백을 함께 개편

현재 설문은 12개 상황에서 한 선택지를 고르고 축별 양의 선택지 수로 보정한다. 코드가 세 점수를 합계 100으로 정규화하는 것은 아니다. 다만 선택지가 서로 경쟁하므로 **여러 경험을 동시에 원하는 정도를 표현하는지**를 검증해야 한다.

### 설문 초안

- 짧은 상황형 문항과 한국어 모바일 흐름을 유지하되, H/E/R 기대를 각기 답할 수 있는 9–12개 응답 항목을 후보로 만든다.
- H: 실제 역사·전통과 연결되기를 원하는 정도. E: 알고 있던 이미지·상징·장면을 경험하고 싶은 정도. R: 자유·회복·몰입·관계를 원하는 정도.
- 한 축을 선택하지 않았다는 사실을 그 축을 싫어한다는 증거로 바꾸지 않는다.
- `중요하지 않음`, `낮은 강도를 원함`, `피하고 싶음`, `모르겠음`을 구분한다. 중요도와 선호하는 경험의 강도를 같은 숫자로 섞지 않는다.
- 업로드 사진의 색감·구도 취향은 사용자가 확인한다. 사진 한 장이 설문의 H나 R 욕구를 임의로 덮어쓰지 않는다.
- 질문 문구, 채점 행렬, 설명 문구, API 계약을 같은 의미 버전으로 묶는다. 문구만 바꾸고 과거 채점 의미를 유지하는 방식은 이번 의미 개편에 쓰지 않는다.

사용자 기대 문항은 연구·여행 경험 검토와 인지 면담을 통해 적합성·누락·이해 가능성을 확인한다. 측정하려는 개념과 문항의 관계를 먼저 검토한다는 원칙을 참고하되, 보건 척도용 검증 기준이나 표본 수를 관광 서비스에 그대로 가져오지 않는다. [내용 타당도 방법론](https://doi.org/10.1016/j.jclinepi.2025.111879)

### 추천식과 설명

새 설문에서 중요하지 않은 축은 기본적으로 비교 가중치를 낮추거나 제외한다. 사용자가 실제로 원하지 않는 경험만 별도 불일치 대상으로 둔다. 현재의 `100 − 절대 차이` 방식과 중요도 기반 기대 충족 방식을 동일한 개발 입력에서 비교하고, 기본식을 선택한 뒤 사진·SNS 실험에서는 고정한다.

결과 화면은 “H 진정성 85점” 대신 사용자가 이해할 수 있는 경험과 근거를 설명한다. 예: “실제 남아 있는 유적과 관련 해설을 볼 수 있어 역사 경험 기대와 연결됩니다”, “작품을 통해 알려진 장면을 현장에서 재현할 수 있습니다”, “자연 환경과 체험 활동이 있지만 실제 고요함은 미확인입니다.”

방문 후에는 H/E/R 각각의 기대 충족·불일치와 실제로 느낀 의미·자유·몰입을 묻는다. 장소 특성 평가와 개인의 경험 평가를 다른 테이블에 저장한다. 개인이 덜 만족했다고 장소의 역사 사실을 변경하지 않는다.

설문→사진 선택/건너뛰기→추천→근거 확인→비교→저장→피드백 흐름을 유지하고, 사진·SNS·일부 축이 없을 때도 실제 상태에 맞는 결과를 보여준다.

## 9. 데이터와 인간 평가 설계

### 자료의 역할을 나누기

| 묶음 | 기본 규모안 | 용도 / 제한 |
|---|---:|---|
| 기존 동결 자료 | 2,000곳 | 전수 규칙 감사·개편 전후 회귀·개발. 새 블라인드 자료가 아님 |
| 개발 검수 장소 | 120곳 | 기존 진단 12곳 + 층화 추출 108곳. 항목·정책·가중치 개선 |
| Instagram 초기 탐색 | 40곳 | 한국어 태그 대응·반환 품질·비용·의미 표현 확인. 개발 검수와 일부 중복 가능 |
| 새 장소 평가 | 60곳 목표 | 모델·정책 개발에 노출되지 않은 장소를 별도 확보하고 새 평가로 봉인 |
| 시각 관찰 검수 | 240장 목표 | 개발 180장·새 평가 60장. 사진 수와 장소 수를 구분 |
| 설문 인지 면담 | 약 8명 | 문항 이해·부담·응답 과정 개선. 최종 사용자 평가와 구분 |
| 온라인 사용자 평가 | 60명 목표 | 실제 기대 입력·추천 적합성·설명 이해. 자동 생성 프로필로 대체 불가 |
| 방문 경험자 평가 | 18명 목표 | 방문 시점·활동 맥락에 따른 실제 H/E/R 경험 검토 |

규모는 인력·예산·완료일에 따라 첫 단계에서 확정한다. 축별·하위 집단별 검정력을 이 숫자만으로 보장하지 않는다. 개발 검수의 목적 사례 12곳은 오류 빈도 추정에서 분리하고, 나머지 추출 규칙·층·선정 확률을 기록한다.

새 장소는 기존 장소 ID만 비교하지 않고 동일 명칭·좌표·중복 그룹도 제외한다. 기존에 어떤 분석·검토에 노출됐는지 기록한다. 새 평가의 원문이나 라벨을 보고 설계를 조정하면 그 자료는 이후 개발 자료로 취급한다. 새 사람의 라벨을 기존 2,000곳에서 얻는 것은 가능하지만, 이를 “새 장소 일반화 평가”라고 부르지 않는다.

### 검수자의 역할

두 명이 모델 결과를 보지 않고 독립 평가하고, 불일치를 조정하는 역할을 둔다. 실제 확보되지 않은 검수자·전문가·참가자를 확보한 것으로 표시하지 않는다. 관광 이론의 항목 타당도 검토와 원문·사진의 증거 적합성 검토를 구분한다.

검수는 다음 순서로 진행한다.

1. 장소와 출처가 맞는지, 무엇을 직접 확인할 수 있는지 기록한다.
2. 원형/재현, 이미지의 내용/확산, 활동 기회/실제 경험을 구분한다.
3. 모델 점수 없이 하위 항목의 0–4 또는 UNKNOWN을 평가한다.
4. 사진에서는 먼저 관찰만 평가하고, 이후 축 연결의 타당성을 평가한다.
5. 모델 결과를 공개해 오류 원인을 분류하고 수정 제안을 기록한다.

### 평가 지표

| 평가 층위 | 지표 | 분모·주의점 |
|---|---|---|
| 출처·구조 | 원문 매핑, 권한, 장소 대응, 스키마, 재계산 위반 | 전수 검사. 정확도·만족도와 구분 |
| 의미 적합성 | 실제로 뒷받침되는 주장 비율, 대상 혼동, 부재→0, 허용 범위 초과 | 사람 검수된 주장 기준, 축·오류 유형별 보고 |
| 미확인 처리 | UNKNOWN 정밀도·재현율, 잘못된 0점 비율 | 미확인 예측으로 모든 어려운 항목을 회피하는지 함께 검사 |
| 항목·축 점수 | 0–4 항목 MAE, 축 MAE, 순위 상관, 검수자 간 일치도 | 같은 새 루브릭에서만 수치 비교. 합의 전 일치도도 보존 |
| 사진 | 관찰 유무/UNKNOWN 정확성, 강도 오차, 잘못된 축 연결 비율 | 장소 단위로 묶어 불확실성 계산. 같은 장소의 사진을 독립 장소처럼 세지 않음 |
| SNS | 태그 대응 정확성, 누락률, 관련 표본 비율, 관측 시점·비용 | 표본 관련 비율을 전체 태그 모집단 비율로 단정하지 않음 |
| 추천 | 사람 관련성 라벨이 있는 NDCG@5, 쌍대 선호, 불일치 경고의 적절성 | 작성 시나리오나 모델 판정을 사람 관련성 라벨로 사용하지 않음 |
| 사용자 경험 | 기대 충족, 설명 이해, 사진 수정 성공, 전체 흐름 완료 | 사용자·방문 시점·실제 경험 여부 구분 |
| 편중·안정성 | 지역·유형·SNS 규모·사진 유무별 자격/노출/오류, 중복 사진·결측 민감도 | 유명 장소 노출 증가를 품질 향상으로 해석하지 않음 |

NDCG는 비교 시스템의 추천 후보 합집합을 가린 순서로 제시해 사용자가 관련성을 평가하는 방식으로 수집할 수 있다. 평가하지 않은 장소를 자동으로 0점 처리하지 않고, 사용한 후보 풀과 라벨 범위를 기록한다. 방문 경험이 없는 장소에 대한 관련성 평가는 기대 적합성이지 실제 방문 만족도가 아니다.

95% 신뢰구간은 주된 관측 단위에 맞춰 계산한다. 추천 평가는 사용자 단위, 장소/사진 평가는 장소 단위의 묶음을 고려한다. 60명의 여러 응답을 모두 독립 사용자처럼 세지 않는다. 여러 비교에서는 주된 비교를 하나 정하고 나머지는 탐색적 결과로 구분한다.

장소의 하위 항목은 서로 다른 경험 요소를 모으는 지표일 수 있으므로 높은 내적 일관성만을 목표로 삼지 않는다. 사용자 설문도 소규모 조사만으로 3요인 구조가 확립됐다고 주장하지 않는다. 내용 타당도와 응답 이해를 먼저 확인하고, 충분한 표본의 구조 검증은 별도 과제로 남긴다.

## 10. 비교 실험과 채택 기준

### 실험 조건

| 조건 | 변경 | 확인할 질문 |
|---|---|---|
| L0 | 기존 동결 시스템 | 과거 결과·운영 기준 재생. 새 루브릭 점수와 동일 척도 MAE 비교는 하지 않음 |
| A0 | 오류 처리 개선 + 새 이론·설문·텍스트 평가 | 새로운 정의의 기본 시스템이 의미적으로 타당한가? |
| A1 | A0 + 사진의 E/R 기여 | 시각 관찰을 추가하는 이득과 오류는 무엇인가? |
| A2 | A1 + 조건부 H 사진 기여 | H 보완이 실제로 타당하며 유용한가? |
| A3 | 개발에서 선택한 사진 조건 + SNS 건수 | 이미지 확산 지표만 추가했을 때 효과와 인기 편중은 무엇인가? |
| A4 | 같은 사진 조건 + SNS 건수·표현 의미 | 확산과 의미를 함께 분석하는 것이 건수만 사용하는 것보다 나은가? |

주된 확증 비교는 **A0와 개발에서 동결한 최종 후보**다. A1–A4의 채택 여부는 개발 자료에서 결정한다. 새 평가 결과를 보고 A1–A4 중 가장 잘 나온 것을 최종 후보로 골랐으면 탐색적 선택으로 보고하고 새 확증 자료가 필요하다.

사진 실험에서는 텍스트 판단·설문·기본 추천식을 고정한다. SNS 실험에서는 선택된 사진 정책을 고정한다. 동일한 모델 요청은 검증된 응답을 재사용하고, 입력이 실제로 다른 경우에만 새 추론을 한다. 통합 입력으로 생성한 판단에서 나중에 인용만 가려 출처 제거 실험처럼 표시하지 않는다.

동일 후보 교집합에서의 비교와 실제 자격 필터를 적용한 전체 후보 비교를 둘 다 보고한다. 자료 추가로 추천 가능한 장소 수가 늘어난 효과와 동일 장소의 순위가 바뀐 효과를 분리한다. L0와 새 시스템의 전체 사용자 흐름 비교는 설문·정의까지 달라진 패키지 비교라고 명시한다.

| 단계 | 통과해야 하는 조건 | 통과하지 못하면 |

의미 정밀도·UNKNOWN 오분류·항목 MAE 등에 대한 수치 허용치는 **개발 초기의 사람 간 일치도와 오류의 피해를 근거로 정하고 새 평가를 열기 전에 동결**한다. 이번 계획에서 검증되지 않은 가중치나 보편적 정확도 기준을 만들어 확정하지 않는다. 대신 중대한 장소 오연결·허용하지 않은 사실 추론은 발견 상태에서 그대로 출시하지 않는 원칙을 둔다.

“추천 품질이 향상됐다”는 주장은 사전 지정한 사용자 관련성/쌍대 선호의 비교 결과와 신뢰구간이 뒷받침할 때만 한다. 신뢰구간이 무차이를 포함하면 효과 미확정으로 보고한다. 그 경우에도 인용 오류 감소·재현성·설명 개선처럼 별도로 확인된 결과는 해당 범위에서 보고할 수 있다.

평가 계획·제외 기준·주된 비교·분석 코드를 결과 확인 전에 기록한다. 기존 자료 사용과 이후 변경 사항을 공개해 탐색과 확증을 구분한다. [사전 등록 원칙](https://www.cos.io/initiatives/prereg)

## 13. 버전·자원·복구·배포

새 산출물은 예를 들어 `artifacts/authenticity-v1/<run-date>/` 아래에서 `baseline/`, `sources/`, `observations/`, `assessments/`, `development/`, `new-evaluation/`, `release/`로 구분한다. 이름은 계획안이며 폴더를 만들었다고 단계 완료로 표시하지 않는다.

고정해야 하는 값은 construct/rubric, questionnaire, source authority, photo observation/selection/mapping, social collection/mapping/transform, aggregation, ranking, dataset membership, evaluation protocol, 모델·프롬프트·코드·응답 해시다. 같은 요청과 같은 고정 자료는 저장된 결과를 재생하며 외부 웹의 현재 값으로 과거 추천을 바꾸지 않는다.

새 평가 분할을 소스 코드·가중치 선택 과정에서 접근하지 못하게 하는 검사와 노출 기록을 둔다. 기존 평가 보고서의 해시를 수정해 새 보고서처럼 만들지 않는다.

GLM은 텍스트·사진·복구 작업을 합쳐 동시 5세션으로 운영한다. 429에서는 공유 `Retry-After`와 지수 대기를 지키며 자동 재개한다. 현재 연결 오류의 제한된 재시도와 배치 PAUSED 동작을 유지한다. 공식 TourAPI·Odii·관광사진 한도에 도달하면 새 요청을 중단하고 자동 재시도하지 않는다. 사용자 예산·시간 상한에 도달한 작업은 429 재시도 정책과 별개로 중단 상태를 기록한다.

전체 소요 시간과 GLM 비용은 40곳/개발 표본의 실제 텍스트 길이·이미지 수·토큰·재시도·429 대기·실행 시간을 측정한 뒤 추정한다. 2,000곳×고정 단가나 동시 세션 수만으로 완료 시간을 보장하지 않는다.

배포는 새 후보 생성, 품질 검증, 실제 API/UI 검사, 복구 점검을 완료한 후 활성 버전을 전환한다. 전환 전후 candidate·DB migration·API·frontend release를 기록한다. 사진/SNS 실패 시 검증된 텍스트 기반 경로를 사용하고 새 값을 조용히 0으로 넣지 않는다. 구버전 결과는 재생할 수 있게 유지한다.

## 14. 완료의 정의와 첫 실행 순서

이번 **계획 작성**의 완료는 근거·설계·작업 순서·평가·자원·결정 사항을 이 문서에 명시하고 사용자가 검토할 수 있게 제공하는 것이다. 실제 개편 완료와 구분한다.

개편 완료 시에는 다음 자료가 있어야 한다.

1. 이론→하위 항목→설문→출처 권한→평가 지표가 연결된 버전 문서.
2. 기존 2,000곳과 새 버전 결과를 함께 재생할 수 있는 데이터·코드 계보.
3. 출처·사진·SNS의 실제 품질과 누락, 사진의 축 기여를 검수한 결과.
4. 사람의 평가와 자동 검사를 구분한 비교 실험 보고서. 확보하지 못한 평가는 미완료로 표시.
5. 원문·사진·사회적 이미지 근거와 미확인·불일치를 설명하는 전체 사용자 흐름.
6. 비용·한도·중단·재개·삭제·롤백을 확인한 운영 기록.
7. 전체 장소 검색, 대표 사례, 출처별 기여·제거 비교, 사용자 평가·불확실성을 담은 새 HTML 보고서.

실행을 시작할 때의 첫 순서는 **결정 기록 확정 → 기존 기준 동결 → 진단 12곳으로 새 루브릭·권한표 작성 → 검수자와 내용 타당도 검토 → 40곳 사진/SNS 탐색 계획 및 비용 상한 동결**이다. 그 결과를 확인한 뒤 개발 표본과 전수 적용으로 넓힌다.
