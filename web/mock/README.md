# UI 테스트용 목업

`web/`에서 `pnpm dev:mock` 실행 후 <http://127.0.0.1:3012/start>를 연다.
Node만 사용하며 Python, Docker, DB, API 키가 필요 없다. 중지는 터미널에서 Ctrl+C.
기본 목업 API는 127.0.0.1:8020이며 두 서버 모두 로컬 인터페이스에만 바인딩한다.
포트 변경: `ITDA_MOCK_WEB_PORT=3013 ITDA_MOCK_API_PORT=8021 pnpm dev:mock`.

- 여행 조건 → 프론트 질문 12개 → 목업 프로필 → 현재 추천 화면(`/recommendations/a-…`) → 사진·소개·상세 근거·지도 링크를 확인한다.
- 프로필의 **사진으로 추천받기** → 사진 선택 → **사진 분위기로 추천 보기**로 사진 입력부터 추천 결과까지 확인한다. 내부 태그는 표시하지 않고 샘플 분위기를 모두 자동 반영한다.
- 기존 테스트 결과가 있으면 `/start`에서 조건을 반영한 뒤 바로 프로필로 이동한다. 다시 테스트하려면 **처음부터 시작하기**를 선택한다.
- 상단 목업 설정에서 **다음 추천 요청**을 정상 / 추천 부족 / 서버 오류로 바꾼다. 프로필 화면에서 추천 버튼을 누르면 해당 상태를 볼 수 있다. 이미 열린 추천 결과는 보존한다.
- 목업 초기화는 현재 브라우저의 ITDA 입력·저장과 목업 세션을 지우고 `/start`로 이동한다.
- 질문 문구는 `src/content/questionnaire.ko.json`, 시작 화면 문구는 `src/content/journey.ko.ts`에서 수정한다.

현재 추천 API(`/v1/authenticity`)는 `src/features/authenticity/__fixtures__/prepared-scenario.json`에 저장된 공개 장소 5곳(천장호·영랑호·전주 경기전·해운대해수욕장·하이커 그라운드)의 자료를 사용한다. 사진은 `public/tourism/`의 실제 관광사진을 로컬에서 제공하며 원본 출처를 유지한다. 현재 제품의 추천 컴포넌트를 그대로 사용하고, 프로필에서 사진·상세 정보를 미리 준비한 뒤 결과로 이동한다.

**점수·순위는 고정된 UI 예시다.** 입력한 답변·지역·필수 시설을 요청에 보관하지만 추천을 새로 계산하거나 필터링하지 않는다. 선택한 조건과 다른 지역의 예시도 나올 수 있으며 상단 목업 표시로 구분한다. 프로필 세 축의 원점수도 항상 50점이다. 분석 품질·조건 충족의 검증에는 사용하지 않는다. 실제 서비스나 유료 모델을 호출하지 않는다.

이전 `/v1/recommendation-runs` API의 합성 응답도 이전 화면 개발용으로 유지한다. 현재 프로필의 추천 버튼은 이 API를 사용하지 않는다.

사진 업로드는 최대 32MiB의 multipart 본문을 읽고 즉시 버리며 디코딩하거나 저장하지 않는다. 실제 모델 대신 고정된 샘플 분위기 8개를 반환하고, 확인·삭제·추천 요청을 세션별로 연결한다. 사진 내용에 따른 점수·순위 계산은 하지 않는다. 상단에서 서버 오류를 선택하면 사진 업로드도 오류를 반환하며, 정상으로 바꾸어 재시도할 수 있다. 운영 정보·날씨와 구형 사진 작업 API(`/photo/jobs`)는 미지원이다. 상세 화면의 여행 기록 저장 응답도 UI 확인용이며, 실제 피드백으로 수집하지 않는다.

프로필·추천·샘플 사진 분석·저장 목록은 서버 메모리에만 보관하며 재시작하면 사라진다. 브라우저별 쿠키로 분리하고 최대 100세션, 세션당 200개 생성 요청과 20개 샘플 사진 분석으로 제한한다. 이전 화면의 저장한 장소와 프로필 참조는 브라우저에 남을 수 있으므로 재시작 후에는 상단 **목업 초기화**를 사용한다.

일반 `pnpm dev` / `pnpm build`에는 목업 환경 변수를 설정하지 않는다. 목업은 별도 `.next-mock` 빌드 디렉터리와 포트를 사용한다. 외부 서비스로 요청을 전달하는 폴백은 없다.

검증:

```sh
pnpm exec vitest run src/api/mock-server.test.ts src/api/authenticity-mock.test.ts
pnpm exec playwright test --config playwright.mock.config.ts
```

Playwright는 실제 로컬 목업 서버에 연결하며 API 라우트를 응답으로 대체하지 않는다. 데스크톱·모바일의 전체 흐름과 오류·부족·초기화, 외부 요청 부재를 확인한다.

디자인 통합 검증은 `pnpm exec playwright test --config playwright.design.config.ts`로 실행한다. 위 흐름에 메인 메뉴와 별도 사진 페이지를 추가로 검사한다. 사진 테스트만 합성 분석·확정 응답을 주입해 선택, 새로고침, 추천 요청의 연결을 확인하며 실제 사진 모델을 호출하지 않는다.
