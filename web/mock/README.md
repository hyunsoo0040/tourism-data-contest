# UI 테스트용 목업

`web/`에서 `pnpm dev:mock` 실행 후 <http://127.0.0.1:3012/start>를 연다.
Node만 사용하며 Python, Docker, DB, API 키가 필요 없다. 중지는 터미널에서 Ctrl+C.
기본 목업 API는 127.0.0.1:8020이며 두 서버 모두 로컬 인터페이스에만 바인딩한다.
포트 변경: `ITDA_MOCK_WEB_PORT=3013 ITDA_MOCK_API_PORT=8021 pnpm dev:mock`.

- 여행 조건 → 프론트 질문 12개 → 목업 프로필 → 가상 추천 5곳 → 상세·비교·저장을 확인한다.
- 상단 목업 설정에서 **다음 추천 요청**을 정상 / 추천 부족 / 서버 오류로 바꾼다. 프로필 화면에서 추천 버튼을 누르면 해당 상태를 볼 수 있다. 이미 열린 추천 결과는 보존한다.
- 목업 초기화는 현재 브라우저의 ITDA 입력·저장과 목업 세션을 지우고 `/start`로 이동한다.
- 질문 문구는 `src/content/questionnaire.ko.json`, 시작 화면 문구는 `src/content/journey.ko.ts`에서 수정한다.
- 가상 장소명은 `mock/data.mjs`의 `names` 배열에서 수정한다.

실제 추천 자료를 로드하지 않는다. `fixtures/grounded-synthetic-v5.json`의 합성 테스트 응답을 사용하고, 장소명·설명을 목업으로 표시한 뒤 프로필·지역·요청과 해시를 다시 연결한다. 프론트의 실제 응답 검증은 그대로 적용된다. 프로필 세 축은 언제나 50점이고 순위는 고정이므로 설문 점수나 추천 품질 평가에는 사용할 수 없다. 지역 선택 목록도 UI 확인용 서울·부산·제주 세 곳뿐이다. 계약에 포함된 공급자·모델 식별자는 응답 형태 재현용이며 실제 조회나 모델 실행 이력이 아니다.

사진 업로드·분석, 운영 정보·날씨 등 방문 참고 정보는 사용 불가 응답을 반환한다. 사진은 건너뛰고 진행한다. 업로드 본문은 디코딩하거나 저장하지 않는다. 방문 후 피드백 화면은 현재 제품에 없어 이 목업에도 포함하지 않는다.

프로필과 추천은 서버 메모리에만 보관하며 재시작하면 사라진다. 브라우저별 쿠키로 분리하고 최대 100세션, 세션당 200개 생성 요청으로 제한한다. 저장한 장소는 기존 UI의 로컬 저장소에 남으므로 재시작 후에는 상단 **목업 초기화**를 사용한다.

일반 `pnpm dev` / `pnpm build`에는 목업 환경 변수를 설정하지 않는다. 목업은 별도 `.next-mock` 빌드 디렉터리와 포트를 사용한다. 외부 서비스로 요청을 전달하는 폴백은 없다.

검증:

```sh
pnpm exec vitest run src/api/mock-server.test.ts
pnpm exec playwright test --config playwright.mock.config.ts
```

Playwright는 실제 로컬 목업 서버에 연결하며 API 라우트를 응답으로 대체하지 않는다. 데스크톱·모바일의 전체 흐름과 오류·부족·초기화, 외부 요청 부재를 확인한다.

디자인 통합 검증은 `pnpm exec playwright test --config playwright.design.config.ts`로 실행한다. 위 흐름에 메인 메뉴와 별도 사진 페이지를 추가로 검사한다. 사진 테스트만 합성 분석·확정 응답을 주입해 선택, 새로고침, 추천 요청의 연결을 확인하며 실제 사진 모델을 호출하지 않는다.
