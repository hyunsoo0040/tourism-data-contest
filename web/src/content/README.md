# 여행 질문 문구 수정

화면의 질문·선택지 문구는 이 폴더에서 수정합니다. 문구 수정에는 백엔드 재배포가 필요하지 않습니다.

- `questionnaire.ko.json`: `/quiz`의 12개 질문 제목(`title_ko`), 설명(`description_ko`), 선택지 문구(`text_ko`). 결과 화면의 현재 답변 요약도 이 문구를 사용합니다.
- `journey.ko.ts`: `/start`의 질문·선택지 표시 이름, 지역·날짜 안내, 시작·설문 화면의 소개 문구. 여행 조건 요약도 같은 선택지 이름을 사용합니다.
- `questionnaire.ts`: 표시 문구를 질문·선택지 ID로 연결하고 누락·중복을 검사하는 코드입니다. 평소 문구를 수정할 때는 변경하지 않습니다.

예: 5번 질문은 `question_id: "q5"`인 항목의 `title_ko`를 수정합니다. 선택지 문구는 `choice_id: "q5o1"` 등의 `text_ko`를 수정합니다. `content_version`도 새 문구 릴리스에 맞춰 올려 Git 변경과 함께 기록합니다.

`question_id`, `choice_id`, 여행 조건의 `value`는 서버가 해석하는 값입니다. 질문·선택지 추가/삭제나 의미·배점 변경은 문구 수정과 별개이며, 새 질문/점수 계약과 평가가 필요합니다. 문구 배열을 재정렬해도 실제 질문·선택지 순서는 바뀌지 않습니다.

`/quiz`는 프론트에서 바로 표시합니다. 결과 제출 시에는 `/v1/questionnaires/current`에서 질문 ID, 선택지 값·축, 순서, 점수표, 버전·해시가 예상과 맞는지 확인한 후 기존 답변 요청을 보냅니다. 연결 실패나 계약 불일치 때는 답변을 보존하고 제출 오류를 표시합니다. 점수 계산은 계속 백엔드가 담당합니다.

기존 `contracts/questionnaire-v2.json`과 백엔드 문구는 이미 배포된 API 및 과거 프로필의 점수 해시 재현을 위한 호환 스냅샷입니다. 새 화면 문구를 수정하려고 그 파일이나 백엔드의 질문 정의를 함께 바꾸지 마세요. 프론트 표시 문구가 백엔드 응답의 문구와 같아야 한다는 제약은 없습니다.

백엔드 없이 시작→12개 질문→제출 오류·답변 보존을 확인하는 브라우저 검사는 `web/`에서 `pnpm exec playwright test --config playwright.frontend.config.ts`로 실행합니다.
